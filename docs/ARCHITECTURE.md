# IGNIS architecture

IGNIS is a standard Next.js App Router application. The browser renders the research interface and performs CSV analysis locally. The only server route is an optional assistant adapter that validates a question and calls an independently configured OpenAI-compatible endpoint when a key exists.

## Request flow

A page route imports typed records from `lib/research.ts`, renders shared components from `components/`, and uses Recharts for visual output. The Data Laboratory reads a user-selected file with the browser File API, parses CSV text in `lib/data-utils.ts`, derives column metadata, and renders only detected values. Nothing is uploaded by the default lab workflow.

The assistant page submits a bounded question to `/api/assistant`. The route uses `AI_API_KEY`, `AI_BASE_URL` and `AI_MODEL` on the server. Without a key, it returns the same deterministic local fallback used by the interface. It never exposes the key or a provider SDK to the browser.

## Repository layout

`app/` contains route pages, global styles and the assistant API route. `components/` contains the shell, navigation, design primitives, logo and chart wrappers. `lib/` contains research records, synthetic demonstration values, fallback answer logic, CSV parsing and statistics. `public/` contains portable static assets and the route manifest. `docs/` contains operations and scientific documentation.

## Design boundaries

There is no required user account, database, cloud storage or managed runtime. An independently managed database can be introduced later behind a server-only repository layer. Recharts is used for numeric charts; the chart data is never generated by an image model. Tailwind classes define the visual system and do not depend on an external stylesheet host.
