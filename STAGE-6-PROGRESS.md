## Dependency vulnerability investigation

The pre-mitigation audit contained one high-severity PostCSS finding and one critical direct Next.js finding.

### PostCSS — mitigated

- Affected package/path: `postcss` `8.4.31` nested under `next@14.2.35` in the pre-mitigation lockfile.
- Advisory family: PostCSS source-map/path disclosure issues, including GHSA-6g55-p6wh-862q, GHSA-fxqj-rqcc-2cmp, and GHSA-r28c-9q8g-f849; npm reported the affected range as `<=8.5.22` with maximum severity high.
- Practical scope: PostCSS is used during the CSS/build toolchain; it is not application data or a runtime API in this project.
- Fix tested: a minimal npm override resolved all PostCSS copies to `8.5.32`.
- Result: the final audit no longer reports PostCSS; clean install, typecheck, and production build passed with the override.

### Next.js — unresolved

- Affected package/path: direct dependency `next@14.2.35`.
- The final audit reports one critical vulnerability aggregate covering multiple Next.js advisories, including Image Optimization API AVIF/SVG RCE advisories and other DoS/SSRF-related ranges. npm reports the safe automatic fix as `next@16.4.5`, which is a breaking major upgrade.
- The current application does not configure `next/image`, rewrites, middleware, Server Actions, or an Edge runtime, which reduces exposure for several advisory paths, but this does not make the dependency clean or safe to ignore for public production hosting.
- No blind `npm audit fix --force` was run. Next.js 14 architecture was preserved as instructed.
- Result: unresolved. A future owner must choose and test either a supported patched Next.js line, likely requiring a controlled major upgrade, or a deployment mitigation that prevents exposure of affected APIs. Do not publish this backup as a security-cleared production release.
